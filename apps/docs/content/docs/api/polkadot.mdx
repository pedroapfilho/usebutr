## Discovery

### `discoverInjectedPolkadotAdapters(onAdapter, options?): () => void`

Reads `window.injectedWeb3` without prompting: adapters are built without
calling `enable()`. It scans at once and again on a poll schedule for
late-injecting extensions; the returned function cancels pending polls. It is
a `WalletSource` as-is:

```ts
import type { WalletManagerConfig } from "@usebutr/core";
import { discoverInjectedPolkadotAdapters } from "@usebutr/polkadot";

const config: WalletManagerConfig = { sources: [discoverInjectedPolkadotAdapters] };
```

`InjectedPolkadotDiscoveryOptions`: `pollMs?: ReadonlyArray<number>` (offsets
in milliseconds, default `[250, 750]`; `[]` for a single synchronous scan) and
`target?` (overrides `window`).

### `discoverPolkadotWalletStandardAdapters(onAdapter): () => void`

Discovers wallets advertising a `polkadot:` chain through Wallet Standard.
Requires `@wallet-standard/app`.

### `polkadotDiscoverer: PlatformDiscoverer`

injectedWeb3 as the primary channel, Wallet Standard as a fallback that runs
only when the first injectedWeb3 scan found nothing. A wallet on both
channels would otherwise list twice under unrelated ids.

## Adapter builders

### `buildInjectedPolkadotAdapter(extensionName, displayName, provider): PolkadotAdapter`

`provider` is the `window.injectedWeb3[extensionName]` entry. The id is
`injected:polkadot:<extension-name>`. `connect()` calls `enable("butr")`,
which may prompt; construction does not. `signMessage` appears once
`connect()` has enabled an extension that exposes `signRaw`, and `subscribe`
once it exposes `accounts.subscribe`. There is no `switchChain`: an injected
extension has no network to switch. An account pinned to a network through
`genesisHash` carries that chain; others are labelled Polkadot.

### `buildPolkadotWalletStandardAdapter(wallet, registerDisconnector?): PolkadotAdapter | null`

Wraps a Wallet Standard wallet, or returns `null` when it speaks no Polkadot.
The id is `slugify("polkadot", wallet.name)`. `signMessage` exists when the
wallet advertises `polkadot:signMessage`, and `switchChain` when it
advertises more than one Polkadot chain.

Neither adapter has `sendTx`, `getBalance` or `getTransactionReceipt`:
building an extrinsic needs chain metadata over RPC, which butr does not
ship.

## Signers

Importing the package registers the `polkadot-injected` kind:

```ts
type PolkadotInjectedSigner = {
  extension: Injected; // the object `enable()` resolved: `accounts` and `signer`
  extensionName: string; // the `window.injectedWeb3` key
  kind: "polkadot-injected";
};
```

It carries no address: sign as the connected wallet's `account`.
`extensionName` is what polkadot-api's `connectInjectedExtension` takes. On an
injected adapter that is not connected, `getSigner()` rejects. Wallet Standard
adapters resolve `{ kind: "wallet-standard", wallet }`. See the
[PAPI integration](/integrations/polkadot).

Injected message signing wraps the bytes in `<Bytes>…</Bytes>` before
`signRaw`; verify against the returned `signedMessage`, which contains the
wrapper.

## Types

`InjectedPolkadotDiscoveryOptions`, `PolkadotSignMessageFeature`,
`PolkadotSignMessageInput`, `PolkadotSignMessageOutput`.

The Polkadot chain registry (`POLKADOT_CHAINS`, `POLKADOT_CHAINS_LIST`) lives
in `@usebutr/core`. Chain ids are `polkadot:` plus the first 32 hex characters
of the genesis hash.
