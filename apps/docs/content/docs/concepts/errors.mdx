---
title: Errors
description: How thrown values from wildly different wallet SDKs become one ConnectionError class you branch on by kind.
---

Wallet SDKs throw inconsistently: MetaMask uses EIP-1193 numeric codes, Phantom
throws stringly-typed errors, embedded SDKs throw their own classes. butr
normalises all of it into one class so you branch on `kind` instead of
regexing message strings.

```ts
type ConnectionErrorKind =
  | "AccountNotExposed"
  | "ChainMismatch"
  | "NotConnected"
  | "RequestPending"
  | "Timeout"
  | "Unknown"
  | "UserRejected"
  | "WalletLocked"
  | "WalletNotFound";

class ConnectionError extends Error {
  readonly kind: ConnectionErrorKind;
  // plus Error's `message`, `name` ("ConnectionError"), and `cause`
}
```

`message` is always human-readable. `cause` keeps the original thrown value, so
you can still inspect the wallet's raw error. It is a real `Error`, so
`instanceof ConnectionError` works and error trackers get a stack.

## Where you meet it

- `useConnect().error` holds the latest failed attempt; `status` is `"error"`.
  `connect(id)` itself never throws.
- `useConnect().connectAsync(id)` and `useWalletManager().connect(id)` reject
  with it, for code that needs the connected wallet as a result.
- `onConnectError(error, connectorId)` receives it for every failed attempt.
- `onHydrated` reports each failed silent reconnect with a `ConnectionError`
  as its `reason`.
- Adapter methods you call yourself (`signMessage`, `sendTx`,
  `signTransaction`, `switchChain`, `getBalance`) reject with it when the call
  names a chain the transport cannot reach or an account the wallet does not
  expose, before the wallet is asked anything.

```tsx
import { useConnect } from "@usebutr/react";

const ConnectError = () => {
  const { error, reset } = useConnect();
  if (error === null || error.kind === "UserRejected") {
    return null; // the user clicked "reject"; usually no UI needed
  }
  return (
    <p role="alert">
      {error.kind === "WalletLocked" ? "Unlock your wallet and try again." : error.message}
      <button type="button" onClick={reset}>
        Dismiss
      </button>
    </p>
  );
};
```

## What each kind means

| Kind                | Raised when                                                                                                                                                                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `UserRejected`      | EIP-1193 code `4001`, or a message containing "user rejected" / "user denied"                                                                                                                                                                                                                     |
| `RequestPending`    | EIP-1193 code `-32002`: the wallet already has a prompt open                                                                                                                                                                                                                                      |
| `WalletLocked`      | a message containing "locked"                                                                                                                                                                                                                                                                     |
| `ChainMismatch`     | an adapter call names a chain its transport cannot reach: another namespace, a chain the wallet does not advertise or the session did not approve, a network the wallet cannot switch to, or any chain but a Ledger adapter's own; also a message about a chain "mismatch" or "unsupported" chain |
| `AccountNotExposed` | an adapter call names an `account` the wallet does not expose                                                                                                                                                                                                                                     |
| `NotConnected`      | EIP-1193 codes `4100` / `4900` / `4901`, a "not connected" message, a wallet that connected but exposed no accounts, or an adapter call while it exposes none                                                                                                                                     |
| `Timeout`           | a connect that did not settle within 90 seconds, or a silent reconnect within 15                                                                                                                                                                                                                  |
| `WalletNotFound`    | `connect(id)` for an id no source announced                                                                                                                                                                                                                                                       |
| `Unknown`           | anything else                                                                                                                                                                                                                                                                                     |

## Normalising your own calls

The manager normalises what it catches. Adapter methods you call yourself
raise `ChainMismatch`, `AccountNotExposed` and `NotConnected` as
`ConnectionError`s, but once the wallet is asked, they reject with whatever it
threw: a declined prompt, a locked wallet, an RPC failure. Pass that through
`toConnectionError` to get the same classification:

```ts
import { toConnectionError } from "@usebutr/core";

try {
  await wallet.connector.sendTx?.(tx, { account: wallet.account });
} catch (raw) {
  const error = toConnectionError(raw);
  if (error.kind !== "UserRejected") {
    showToast(error.message);
  }
}
```

It returns a `ConnectionError` unchanged, wraps any other `Error` with its
classified kind, and turns a non-`Error` value into `Unknown`.

<Callout type="warn">
  Classification is best-effort. A wallet that throws an unrecognised shape lands in `Unknown`. butr
  does no retrying; you decide whether to retry based on `kind`.
</Callout>
